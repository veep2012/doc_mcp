# Technical Debt

Deferred configuration simplification work recorded on 2026-08-11.

## TD-20260811-01

### Title

Separate MCP site configuration from crawler and authentication configuration

### Context

The shared `sites.yaml` loader currently requires `auth_required` and `url` for
every site. MCP startup and its read-only tools do not need either value to
search, list, or fetch an existing index. `auth_required` is only used by MCP
for the display label in `get_sites`; `url` is only displayed in MCP startup
and `get_sites` output. The MCP path does require `name` and `index_file`, with
search/vector settings affecting optional search behavior.

### Location

- `src/docmcp/config/loader.py`
- `src/docmcp/tools.py`
- `src/docmcp/main.py`
- `src/docmcp/crawl_cli.py`
- `src/docmcp/auth/session.py`
- `src/docmcp/auth_cli.py`
- `src/docmcp/vectorize_cli.py`
- `config/sites.yaml.example`
- `documentation/configuration.md`

### Impact/Risk

MCP-only deployments must provide crawler and authentication fields that are
irrelevant to serving a prepared index. This increases configuration noise,
creates false validation failures, and makes it harder to understand which
settings affect MCP behavior. The current shared validation also makes future
MCP-only configuration changes coupled to Playwright and crawl schema rules.

The audit also found these additional candidates for separation: `session_file`,
the `playwright` block, and the `crawl` block are crawler/auth-only; vector
`chunk_size` and `chunk_overlap` are vector-index build settings, while
`vector_index_file` and `vectorizer.embedding_model` remain relevant to MCP
vector search. `respect_robots_txt` appears in the sample but is not consumed
by the current crawler.

### Why Deferred Now

The current request is to capture the configuration redesign as technical debt,
not to change validation behavior or migrate existing workspaces. Removing
required fields without first defining compatibility and mode selection could
break crawler and authentication workflows.

### Proposed Fix

Introduce explicit configuration profiles or loaders for `mcp`, `crawl`, and
`auth` while retaining shared path and environment-variable resolution. The
MCP profile should accept a minimal site entry such as:

```yaml
sites:
  - name: "Prepared Docs"
    index_file: "index/prepared.db"
```

For MCP, `search_engine` should default to `hybrid`, `vector_index_file` should
remain optional and derive from `index_file`, and the embedding model should
default to the runtime default. `url` may remain an optional display metadata
field. Crawl/auth profiles should continue requiring and validating their own
fields, including `url`, `auth_required`, `session_file`, `crawl`, and
`playwright` settings. Update examples, documentation, and profile-specific
tests; remove or correct the unused `respect_robots_txt` sample field.

### Acceptance Signal

An MCP server configured with only `name` and `index_file` starts successfully
and supports `get_sites`, `list_pages`, `search_docs`, and `fetch_page`. Existing
crawl and authentication configurations continue to validate and run without
adding MCP-only fields. Tests demonstrate that crawler-only settings are not
required by MCP and that vector search still validates its sidecar/model
compatibility.
