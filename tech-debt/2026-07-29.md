## TD-20260729-01 — Resolve unknown pytest asyncio configuration

- **Context:** Version-bump verification passed, but pytest emitted `PytestConfigWarning: Unknown config option: asyncio_mode`.
- **Location:** `pytest.ini`, test-environment dependencies, and async test configuration.
- **Impact/Risk:** Async tests may not run under the intended pytest mode, and the warning can hide other test-configuration problems.
- **Why Deferred Now:** The warning predates the version bump and the targeted tests passed; changing test dependencies or pytest configuration is outside this version-only change.
- **Proposed Fix:** Install and configure the pytest asyncio plugin used by the repository, or remove/update the stale `asyncio_mode` setting if the project no longer requires it. Verify the full test suite afterward.
- **Acceptance Signal:** Targeted and full pytest runs recognize `asyncio_mode` without warnings, and async tests execute under the intended configuration.
- **Status:** `open`

## TD-20260729-02 — Isolate unexpected page errors during crawling

- **Context:** After authentication succeeds, an unexpected navigation, download, extraction, or page-processing exception can terminate the entire crawl instead of allowing later pages to be processed.
- **Location:** `src/docmcp/crawl_cli.py`, crawl error-handling helpers, crawl result reporting, and `tests/test_crawl_cli.py`.
- **Impact/Risk:** One site-specific or unknown page failure blocks the full crawl, prevents otherwise valid pages from being indexed, and leaves the operator without a concise explanation of which page failed or whether processing continued.
- **Why Deferred Now:** The current work only records the requirement; implementing a consistent error boundary and result contract requires changes across crawl stages and their tests.
- **Proposed Fix:** Add a per-page error boundary covering navigation, PDF download/extraction, content extraction, link discovery, and indexing. Catch expected and unknown exceptions, emit a meaningful structured error containing the URL, stage, exception type, and safe message, mark the page as skipped with a stable reason code, and continue with the remaining queue. Preserve fatal startup/configuration/authentication errors as blockers.
- **Acceptance Signal:** After authentication, any page-level error—including an unknown exception—produces an actionable log/result, the failed page is skipped, subsequent pages are crawled and indexed, the final summary reports skipped pages and reason codes, and startup/configuration/authentication failures still stop the command.
- **Status:** `open`
