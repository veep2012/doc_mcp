## TD-20260729-01 — Support Playwright client certificates in site configuration

- **Context:** A protected LD stage site may require a client certificate in addition to proxy configuration and normal browser authentication.
- **Location:** `src/docmcp/config/playwright.py`, `src/docmcp/auth/session.py`, `src/docmcp/crawl_cli.py`, `config/sites.yaml.example`, `documentation/configuration.md`, and related tests.
- **Impact/Risk:** Users cannot configure mTLS client certificates through `sites.yaml`; authentication and crawling fail when the server requires a client certificate. The current workaround, `crawl.ignore_https_errors: true`, only bypasses server-certificate validation and does not provide client authentication.
- **Why Deferred Now:** The current request is to record the capability for later implementation, not to change the browser configuration schema and runtime flows.
- **Proposed Fix:** Add validated `playwright.context.client_certificates` support for PEM and PFX files, including environment-variable path/passphrase resolution, pass the option to every browser context used by authentication, session validation, crawling, and targeted reindexing, and document the configuration with safe secret-handling guidance.
- **Acceptance Signal:** A configured client certificate is applied to the matching origin in authentication, session validation, and crawl contexts; PEM/PFX configurations are validated; tests cover path-based and environment-resolved certificates; and the example configuration and troubleshooting documentation are updated.
- **Status:** open
