## TD-20260802-01 — Provide an MCP-only wheel

- **Context:** The package currently exposes a single wheel and installs the full dependency set, even when a user only needs the MCP server and its installation footprint.
- **Location:** `pyproject.toml`, `Makefile`, and the package distribution/build documentation.
- **Impact/Risk:** MCP-only installations unnecessarily download and install unrelated dependencies, increasing installation time, disk usage, deployment complexity, and the risk of dependency conflicts in constrained environments.
- **Why Deferred Now:** The current request is to record the packaging limitation for later implementation; changing package metadata, build targets, dependency boundaries, and release validation is out of scope.
- **Proposed Fix:** Define a supported MCP-only distribution or wheel-generation target with only the dependencies required by the MCP server, while preserving the full distribution for authentication, crawling, vectorization, and other workflows. Document the selection and test installation of both artifacts.
- **Acceptance Signal:** A documented MCP-only wheel can be built and installed independently, starts the MCP server successfully, excludes unrelated workflow dependencies, and automated packaging checks verify both the MCP-only and full distributions.
- **Status:** open
