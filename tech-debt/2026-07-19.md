# Technical Debt

Deferred implementation items for the repository.

## TD-20260719-01 — Add opt-in start-URL-only crawl mode

- **Context:** The crawler currently discovers and queues links from the configured `crawl.start_url` and subsequent pages. A configuration key is needed to disable scanning pages outside the configured start URL while preserving the current behavior by default.
- **Location:** `src/docmcp/crawl_cli.py` (`_link_discovery_decision` and the crawl queue in `crawl_site_headful`), `src/docmcp/config/loader.py`, `config/sites.yaml.example`, and crawler configuration documentation/tests.
- **Impact/Risk:** Sites whose start page contains navigation, archive, or recommendation links can currently expand the crawl beyond the intended page. Without an explicit opt-in restriction, users cannot safely limit a crawl to the start page. Any implementation that does not retain URL tracking could also re-enqueue cyclic links and loop through the same pages.
- **Why Deferred Now:** The current task is limited to registering the requirement; implementation and configuration-schema decisions are deferred.
- **Proposed Fix:** Add an opt-in crawl setting (for example, `crawl.restrict_to_start_url: true`) with a default of `false`. When enabled, reject discovered links that resolve outside the normalized `start_url` scope before enqueueing them. Continue tracking normalized URLs in `visited` and `queued`, and reject links already present in either set, including links that form navigation loops. Add debug/reason messages and tests for default behavior, restricted behavior, normalization, and cyclic links.
- **Acceptance Signal:** With the setting omitted or `false`, existing crawl traversal is unchanged. With it set to `true`, only the start page is crawled; out-of-scope links are explicitly rejected; cyclic links are tracked and rejected without duplicate requests or an infinite crawl.
- **Status:** `open`
