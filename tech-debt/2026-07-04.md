## TD-20260704-01
- Title: Add page-only revectorization with sidecar consistency guards
- Context: While narrowing selected-page reindexing to crawl-only behavior, incremental vector updates were identified as a separate follow-up.
- Location: `src/docmcp/vector_index.py`, `src/docmcp/vectorize_cli.py`, `documentation/crawling.md`, `documentation/configuration.md`
- Impact/Risk: The vector sidecar is currently rebuilt as a full pass. If we later add page-only vector refresh without strict compatibility checks, mixed embeddings or stale chunks could degrade semantic search quality.
- Why Deferred Now: The current change is intentionally limited to crawl-side page selection and documentation updates. Incremental vector updates would require additional sidecar validation, delete/replace behavior, and regression coverage.
- Proposed Fix: Add an explicit incremental revectorization flow that replaces chunks for selected pages only, while enforcing same-model, same-chunking, and sidecar freshness checks.
- Acceptance Signal: A targeted vector update command exists, refreshes only selected pages, rejects incompatible sidecars, and leaves unrelated search results stable in regression tests.
- Status: open
